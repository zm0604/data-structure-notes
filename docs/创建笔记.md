# VSCode + Markdown 数据结构笔记搭建与 Git 同步操作指南
> 本指南用于从零搭建 GitHub 托管的数据结构笔记仓库，使用 Markdown 记录、VSCode 编辑、Git 做版本管理，解决 HTTPS 推送超时问题，适合长期维护学习笔记。

## 一、前期准备

1. 注册并登录 GitHub 账号
2. 下载安装 Git for Windows：官网 `git-scm.com`，安装过程保持默认选项
3. 下载安装 VSCode

## 二、第一步：GitHub 上新建远程仓库

1. 登录 GitHub，页面右上角 `+` → `New repository`
2. 仓库基础配置
   - Repository name：`data-structure-notes`
   - Description：`数据结构学习笔记，包含知识点、图解、C/C++代码、习题`
   - Visibility：**Public**（公开仓库，可作为简历项目展示；仅自己使用可选择 Private）
3. 勾选 `Add a README file`；`.gitignore` 选择 `None`；License 选择 `MIT`（公开仓库推荐）
4. 点击 `Create repository`，完成远程仓库创建

## 三、第二步：将远程仓库克隆到本地
> 说明：克隆会把 GitHub 仓库完整下载到本地，自动生成 Git 版本库（隐藏文件夹`.git`，请勿删除、修改）

1. Git 基础身份配置（仅首次安装 Git 执行一次）
    打开 Git Bash，执行下面两行命令，替换为你自己的 GitHub 用户名、绑定邮箱：
    ```
    git config --global user.name "你的GitHub用户名"
    git config --global user.email "你GitHub绑定的邮箱"
    ```
    校验配置是否成功：
    ```
    git config --global --list
    ```
    输出中能看到刚才填写的用户名和邮箱即为配置成功。
2. 获取仓库 HTTPS 地址
    ```
    https://github.com/你的用户名/data-structure-notes.git
    ```
    
    1. 浏览器打开刚建好的仓库主页
    2. 点击页面绿色 `Code` 按钮，选择 `HTTPS`
    3. 点击复制图标，复制仓库地址，格式示例：
3. 选择本地存放目录
    建议放在非 C 盘，路径不要包含中文、空格、特殊符号，示例路径：`D:\github`
    在目标文件夹空白处右键 → `Git Bash Here`，打开 Git 命令行窗口。
4. 执行克隆命令
    将复制好的仓库地址粘贴执行：
    ```
    git clone https://github.com/你的用户名/data-structure-notes.git
    ```
    正常成功输出参考：
    ```
    Cloning into 'data-structure-notes'...
    remote: Enumerating objects: 3, done.
    remote: Counting objects: 100% (3/3), done.
    remote: Compressing objects: 100% (2/2), done.
    remote: Total 3 (delta 0), reused 0 (delta 0), pack-reused 0
    Receiving objects: 100% (3/3), done.
    ```
    执行完成后，文件夹内自动生成 `data-structure-notes` 仓库文件夹。
5. 使用 VSCode 打开仓库
> ⚠️ 重要：必须打开仓库根目录，不要单独打开某个 md 文件，否则相对路径、Git 识别会出错

    ```
    data-structure-notes/
    ├── README.md                # 仓库首页介绍、学习进度
    ├── docs/                    # Markdown笔记主体
    ├── code/                    # C/C++配套实现代码
    └── assets/                  # 笔记配图、流程图截图
    ```
   1. 打开 VSCode，顶部菜单：`文件 → 打开文件夹`
   2. 选中 `D:\github\data-structure-notes`（仓库根目录），确认打开
   3. 在资源管理器新建规划目录（推荐目录结构）

## 四、第三步：配置 SSH（解决 HTTPS 推送 GitHub 超时、连接失败）
> 说明：默认 HTTPS 方式经常出现 443 端口连接超时报错，SSH 方式稳定性更好，配置完成后不再需要输入 Token，一次配置永久使用。

1. 生成 SSH 密钥（仅需要配置一次）
    打开 Git Bash 执行命令，替换为你的 GitHub 绑定邮箱：
    ```
    ssh-keygen -t ed25519 -C "你github绑定的邮箱"
    ```
    弹出提示时全部直接回车，不要设置密码。
2. 获取公钥内容
    密钥生成完成后，公钥文件路径：
    ```
    C:\Users\你的用户名\.ssh\id_ed25519.pub
    ```
    使用记事本打开该文件，完整复制里面全部内容。
3. 在 GitHub 添加公钥
   1. GitHub 网页右上角头像 → `Settings`
   2. 左侧菜单找到 `SSH and GPG keys` → 点击 `New SSH key`
   3. Title 填写备注（如 `vscode-ds-notes`），Key 输入框粘贴刚才复制的公钥，点击 `Add SSH key`
4. 修改仓库远程链接为 SSH 地址
    VSCode 打开终端（快捷键 `Ctrl +``），确认当前路径在仓库根目录，执行：
    ```
    git remote set-url origin git@github.com:zm0604/data-structure-notes.git
    ```
5. 连通性测试
    ```
    ssh -T git@github.com
    ```
    输出 `Hi 你的用户名! You've successfully authenticated` 代表 SSH 配置成功。

## 五、第四步：VSCode 内编写笔记 & 同步更新到 GitHub

### 5.1 新建 Markdown 笔记文件

1. 左侧【资源管理器】，打开 `docs` 文件夹
2. 在 `docs` 上右键 → 新建文件
3. 填写文件名，**必须以 `.md` 作为后缀**，示例：`01-绪论.md`
> 命名规范：使用数字 + 短横线，尽量不使用空格，方便管理排序

### 5.2 笔记编辑与预览

1. 打开 md 文件，使用 Markdown 语法书写笔记，支持 Mermaid 流程图、LaTeX 数学公式、代码块
2. 推荐插件：`Markdown Preview Enhanced`，安装后右键编辑区，选择 `Markdown Preview Enhanced: Open Preview to the Side`，左右分屏实时预览渲染效果

### 5.3 Git 同步完整工作流（图形界面方式）

快捷键 `Ctrl+Shift+G` 打开【源代码管理】面板

1. **修改文件**：写完笔记、新增图片 / 代码，保存文件
2. **暂存更改**：点击「暂存所有更改」，将本次修改加入暂存区
3. **填写提交信息**：在顶部输入框填写规范提交消息，格式：`类型: 描述内容`
   - `docs`：修改、新增笔记文档（最常用）
   - `feat`：新增代码、新增章节
   - `fix`：勘误、修复代码 bug
   - `chore`：整理目录、配置文件
   示例：`docs: 完成绪论笔记，补充复杂度说明`
4. **提交**：点击【提交】，生成本地版本快照（此步骤仅保存在本地，不需要联网）
5. **推送**：提交成功后点击【推送】，将本地版本上传同步到 GitHub 远程仓库

> 补充：终端命令版本（图形界面异常时使用）
```
# 暂存全部改动
git add .
# 本地提交
git commit -m "docs: 完成绪论笔记，补充复杂度说明"
# 推送到远程
git push
```

## 六、常见问题说明

1. `fatal: unable to access ... Could not connect to server`
原因：HTTPS 网络访问超时。解决方案：按本指南配置 SSH，或者切换手机热点重试。
2. 提交时页面卡住，没有下一步
VSCode 设置搜索 `Git: Use Editor As Commit Input`，取消勾选，重启 VSCode，提交前务必填写提交信息。
3. 图片在 GitHub 网页打不开
图片统一放在 `assets` 文件夹，使用**相对路径引用**，示例：`![示意图](../assets/xxx.png)`，禁止使用电脑本地绝对路径。
4. 推送提示冲突（rejected）
代表远程仓库存在新的修改，先拉取远程内容合并：`git pull origin main`，处理冲突后再推送。
